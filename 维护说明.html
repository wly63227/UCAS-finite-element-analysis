维护与更新#

教材正文只改 笔记整理/*.md，不改 .vitepress/dist/。history/notes-before-2026-10-20.zip 为旧稿快照，不是另一套待维护正文。

新资料到来#

  1. 将新 PDF 或图片放入工作区，执行 python scripts/inventory.py。该脚本只读原件，记录哈希和文本可提取状态；大书提取可能较慢。先对比既有 sources.json，保留稳定来源 ID 和已核实状态，内容变化时重新审阅。
  2. 实际查看所有新课堂页。对图、公式与扫描页视觉核查；无法辨认的内容明确记录，不依靠 OCR 猜测。PDF 统一从 1 开始的物理页码。
  3. 编辑受影响正文，更新 coverage.json、knowledge.json 和对应 Markdown 索引。旧 kp-... 锚点不得因重排而改号；新增知识点另取新编号。
  4. 重跑数值模型和图，核对适用条件、单位、法向、自由度与矩阵维度。重要数学修正写入勘误。
  5. pnpm check。若有意修改历史公式或移除内容，应说明理由，再执行 node scripts/check.mjs --update-baseline --reason "具体修正原因"，检查基线差异，禁止为掩盖失败直接关闭门禁。
  6. pnpm build，再运行 pnpm check 检查实际 HTML 链接和公式错误。浏览器检查桌面/窄屏、深色、搜索、交互、无 JS 基础阅读。
  7. 提交源码与索引后由 GitHub Actions 部署。线上 URL 与 commit 未核实时，不记“发布成功”。

scripts/prepare.mjs 是本次初始迁移的索引生成器。后续可用作辅助，但须审阅其自动分类；它不会替你核实新资料，不能原样重跑便宣称新增页面已覆盖。已知点直接维护 JSON 与稳定锚点。

质量门禁的边界#

基线检查能发现已有公式或知识条目意外删除，但无法证明每条数学断言正确。计算检查验证具体模型与边界，不证明任意几何下的理论。浏览器抽样不等于全站所有设备或真实学生学习实验。最终报告必须分别写明这些范围。
